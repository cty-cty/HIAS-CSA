# HIAS-CSA 网页与使用流程设计方案

日期：2026-10-07。状态：2026-10-07 用户批准复核后实施，本地预览优先。用户已明确要求外观升级、操作效率和规则可理解性“都要”。

## 目标与依据

面向现有项目适用人群，让用户比较课程、形成预选方案、检查培养缺口与已知排课冲突、导出课表。三项目标同时满足：第一屏结构变化明显；重复选课操作更少；用户能够理解课程为何计分、推荐为何出现，以及哪些事项仍需核对。

本轮依据当前源码、此前用户截图与反馈。浏览器读取线上标签页超时，未完成当前线上视觉复核。文中的体验问题属于源码支持的设计判断，不冒充用户测试结果。项目摘要中的旧发布状态不沿用，当前会话已确认上一版上线。

## 三种路线与推荐

| 路线 | 外观变化 | 流程收益 | 代价与适用情况 |
|---|---|---|---|
| A：选课工作台，推荐 | 导航、课程列表、方案面板整体重组 | 比较、缺口处理与课表核对处在同一工作区 | 需要重排界面，但复用现有规则与数据 |
| B：步骤向导 | 新手引导更鲜明 | 首次配置容易理解 | 反复改课时步骤较多，适合作为首次配置补充 |
| C：视觉加强版 | 卡片、配色、动画更明显 | 结构和流程改善有限 | 改动较小，但仍可能重复上一轮变化不明显的问题 |

选择 A 作为主方案，把 B 的轻量首次配置融入 A；C 的视觉细节作为系统规范。主要变化来自结构和任务组织。

1440px 视口采用约 144px 导航、可伸缩主体和 320px 方案栏，间距 24px；最大工作区约 1376px。1024px 附近导航转顶部、方案栏变抽屉，优先保证课程内容宽度。规则页和数据页沿用同一导航与标题层级。

课程默认使用对齐的列表行，方便横向比较教师、学分和考核方式；保留卡片视图供偏好浏览的用户切换。排课复杂时先显示第一组与“另有 N 组安排”，展开后完整列出日期、节次、周次和教室。不得漏掉多组、单双周或跨学期信息。

## 视觉系统

- 品牌与主操作：学院深蓝 #234C89；文字 #182E49；背景 #F4F6FA；内容 #FFFFFF；边界 #DCE4EE；辅助文字 #54657B。
- 成功 #276554、冲突 #A52D41，待核对使用单独警示样式；全部搭配文字和图标，不能只靠颜色区分。警示色与文字色在实现时实际测量对比度。
- 中文采用本机无衬线字体：PingFang SC / Microsoft YaHei / sans-serif，离线无需加载外部字体。正文 16px、辅助信息 14px、课程名 18px、页标题 24px；数字等宽。
- 导航、课程行、筛选条、方案面板各有明确层级，不把所有内容包装成相同圆角卡片。圆角按控件 8px、面板 12px 区分。
- 具有辨识度的核心：学院蓝导航与持续可操作的培养缺口面板。第一屏看得见“课程—方案—待处理事项”的关系。
- 图标统一沿用 Lucide，16/20px 两档；教师、院系、地点、按钮均使用相同基线规则。长教师名、长专业名与两行标签需单独复核。

## 使用逻辑

### 1. 配置与身份

首次进入保留现有培养设置，按身份/方向、英语资格、核对摘要组织；不要求每次进入重复完成。顶部持续显示当前学期和方向。修改身份后保留已选课程，立即重新计算并说明变化。

### 2. 找课与比较

现有代码已按培养方案核心课、专业课等排序，继续复用。增加“本方案核心课”“本方案专业课”“全部课程”快捷范围，它们依据培养方案数据生成，不硬编码学院名单。“避开已知时间冲突”清楚表达检查范围。

搜索、范围、院系等条件用可删除标签显示。无结果时说明当前条件，提供移除某项或清除筛选。查看已选课程时保存浏览状态；返回目录恢复搜索、筛选和滚动位置，替代当前 showSelectedCourses 清空筛选的行为。学期切换时按学期隔离浏览上下文，避免条件误用。

课程行先展示名称、学分、教师、考核和排课；培养分类说明放在可展开内容中，避免所有标签同时争夺注意力。详情保留完整事实与数据来源，不将考核类型推断为难度。

### 3. 形成方案

加入/移除后立即更新右侧门数、学分、有效学分和已知冲突，并复用当前撤销能力。“方案学分合计”与“本学期有效学分”分别标注，英语免修、历史已修、讲座待认定等按现有规则显示明细。

冲突保留允许手动规划的能力；明确列出课程、重合星期/节次/周次，并提供查看班次或移除入口。排课未知显示“时间待确认”，不能标为无冲突。移除已选课程后焦点留在合理的相邻位置。

### 4. 培养缺口

右栏展示当前方案最相关的 2—3 个未满足或待核对项目，其余进入培养进度页查看。区分本学期、培养累计与人工待核对，缺少目标时显示待确认，不能伪造百分比。

点击缺口进入对应课程范围，同时显示触发的筛选条件；返回可恢复原浏览。已完成/待补充/待核对的解释来自确定性规则。一个“本学期检查完成”状态不能被表述为整个培养方案达标。

### 5. 推荐方案

现有推荐已有理由、指标、保留已选和应用确认，本轮主要改为更容易比较的表达。方案表先比较新增门数、有效学分、核心/专业缺口、已知冲突、闭卷/报告门数及已知最高周节数；目标为空时显示待确认。

展开方案再看每门课程的推荐理由、学位归属和待核对项。应用前显示新增课程与变化摘要，继续锁定已有课程；确认后可撤销。没有安全补充方案时解释现有约束，不编造课程、不偷偷放松规则。

### 6. 核对与导出

“我的课表”作为工作区视图，保留周次选择和现有排课计算；从课程进入课表再返回时恢复目录。导出前显示已知冲突/待定排课等提示，保留带提示导出能力。导出格式继续使用现有 WakeUp CSV。

将备份、导入、历史已修、讲座记录等收拢到“工具与数据”内的明确分区，入口保持可发现。批量恢复和清空继续确认，不能把低频破坏性操作放在主操作旁。

## 手机与动作反馈

手机顶部保留学期/方向摘要，课程单列；底部三个主要入口为选课、方案、课表，培养与数据工具通过菜单进入。方案抽屉清楚显示摘要与待处理事项，打开时管理焦点，关闭后回到触发按钮；底部安全区不遮住课程或键盘焦点。

只对操作反馈增加 150—220ms 动画：课程加入后的状态变化、方案列表新增、抽屉展开、缺口数字变更。关闭更快；尊重 prefers-reduced-motion。没有整页漂浮、滚动进场或点击等待动画。保存失败持续可见并提供重试/备份，不能播放成功动画掩盖错误。

## 实施顺序和验收

这是设计路线，不是已执行的实施计划。正式计划应在确认设计后写出文件职责、状态接口和测试用例。

| 阶段 | 交付内容 | 可检查结果 |
|---|---|---|
| 1 结构与视觉 | 导航、课程行、方案栏、桌面和手机样式 | 首屏结构明显不同，375/768/1024/1440px 不横向溢出 |
| 2 浏览流程 | 快捷范围、筛选标签、浏览状态恢复、课表切换 | 查看已选与返回不丢搜索/筛选，切学期不串状态 |
| 3 规则解释 | 培养缺口、推荐比较、计分明细 | 展示值与现有引擎一致，待核对不冒充完成 |
| 4 验收与预览 | 真实状态检查、回归验证、预览对照 | 用同一数据展示改前/改后与完整操作路径，再决定是否发布 |

实施保持现有 React 19、Base UI、Lucide、离线单文件与构建路径。只为展示提取工作台、课程目录、方案面板等组件；推荐/规则引擎继续作为计算来源，不做无关重构。

验收情景：未配置、空选课、普通方案、长课程名、多组排课、未知排课、已知冲突、英语免修、历史已修、讲座待认定、推荐无解、保存失败、备份恢复、学期切换。完整执行三组规则测试、类型/lint、离线和生产构建；视觉一次批量检查桌面/手机，集中修正后最多一次确认，不无限微调。

## 本地实现说明

列表/卡片、侧边导航、工作区课表、方案抽屉、培养快捷范围、会话内按学期保存浏览条件与分页、推荐比较表和理由展开均已接入。课表与方案内容在组件内复用同一 React 内容，避免重复计算和事件路径；没有为提取组件而重构规则层。快捷培养入口保留返回之前目录的条件和滚动，未知排课不绘入课表并明确提示。首次设置、工具分区、备份和数据导入沿用现有能力。

独立源码审查提出滚动位置覆盖和导航键盘方向两项问题，已修正并完成指定问题复核。类型、lint、导航回归、三组规则、离线构建与生产构建的实测结果见主修改清单 15.25。浏览器拒绝 localhost，不能把源码复核、断点 CSS 或构建成功当作实际响应式视觉验收。
